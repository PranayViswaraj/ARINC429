📚 ERROR TYPES EXPLAINED (SIMPLE)
================================================================================

1. NORMAL OPERATION
   Plain English: Everything works perfectly
   How RTL detects: No error flags
   Status: ✓ Safe

2. SINGLE-BIT ERROR
   Plain English: One bit flipped (like one letter in a word changed)
   How RTL detects: Parity check fails
   Status: ✓ Detected and rejected

3. TWO-BIT ERROR ← KEY LEARNING POINT
   Plain English: TWO bits flipped (like two letters changed)
   How RTL detects: CANNOT detect (undetectable!)
   Status: ✗ Silent corruption (dangerous!)
   Why: Two errors cancel in odd parity calculation

4. PARITY ERROR
   Plain English: The parity bit itself is wrong
   How RTL detects: XOR check fails
   Status: ✓ Always detected

5. TIMEOUT / TRUNCATION
   Plain English: Message cut short (like phone call dropping mid-sentence)
   How RTL detects: rx_valid never asserts
   Status: ⚠️ Detected by missing signal pulse

6. INVALID LABEL
   Plain English: Unknown message type (like mail to unknown address)
   How RTL detects: Software label validator
   Status: ⚠️ Rejected at application layer

7. REPEATED ERRORS
   Plain English: Many errors in a row (indicates link degrading)
   How RTL detects: Error counter tracks pattern
   Status: ⚠️ Pattern recognition needed

8. BUS IDLE
   Plain English: No transmission happening (could be normal or broken)
   How RTL detects: Activity monitor
   Status: 🟡 Context-dependent

9. HIGH ERROR RATE
   Plain English: More than 30% of messages corrupted (system failing!)
   How RTL detects: Error rate calculator
   Status: 🚨 CRITICAL - immediate action

Q: What if they ask why two-bit errors aren't detected?
A: Perfect teaching opportunity! Explain:
   - Odd parity checks XOR of all bits = 1
   - Two flipped bits = even number of errors
   - Even errors cancel in odd parity
   - Result: parity_error stays LOW (false negative)
   - This is why critical systems use Hamming codes or CRC

Q: Can I present this without technical background audience?
A: YES! Use the "Plain English" explanations in the guide:
   "Think of parity like checking if a message makes sense.
    If one letter changes, the message seems wrong.
    But if TWO letters change wrong, it might seem right again."

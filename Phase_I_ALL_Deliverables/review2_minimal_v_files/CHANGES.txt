DEFECT -> FIX MAP (defect IDs from the Review-2 audit report)

FI-01  Reset scenarios used `fiu_corrupt = 1'b1 << 12` / `1'b1 << 5` on a
       1-bit reg (evaluates to 0: no fault ever reached the wire).
       FIX: corruption now uses the same time-domain per-bit mechanism as
       the core engine (fiu_corrupt asserted exactly during the target
       serial bit window) + mid-bit wire proof (FIU_in vs FIU_out).
FI-02  Repeated-error reset variant issued the 2nd tx_start while tx_busy
       was high (DUT ignores it: no second transaction existed).
       FIX: variant 3 runs transaction 1 via the engine (fully verified),
       waits for tx_busy==0, then starts transaction 2 and proves both
       [REPEAT-PROOF] lines: "T1 COMPLETED" and "T2 STARTED".
FI-03  Dead conditions `if (rx_valid_count != 0 && 1'b0)` and an empty
       if-block removed. Timeout subtype 2 now snapshots rx_valid_count
       AFTER the engine, waits the full TIMEOUT_THRESHOLD and proves
       rx_valid_count is unchanged.
FI-04  Timeout taxonomy completed (4 honest sub-types):
       0 TRUNCATED_WORD          trailing bits suppressed -> RX completes
                                 a corrupted word (data corruption,
                                 predicted bit-accurately)
       1 SILENT_BUS_ARMED_RX     whole word suppressed, RX armed -> DUT
                                 produces a FALSE RECEPTION (hallucinated
                                 zero word at 15751 cycles) - documented
                                 expected limitation
       2 NO_COMMUNICATION        RX never armed -> no rx_valid within the
                                 threshold (true timeout, before/after
                                 counter proof)
       3 ARMED_RX_NO_TX          RX armed, no TX at all -> hallucinated
                                 zero word predicted and verified
FI-05  expected_limitations increments ONLY after the expected condition
       is verified. Failed verification goes to explicit *_unresolved
       buckets; consistency equation E2 was extended:
       faults_injected == detected + undetected + limitations + unresolved
FI-06  Repeated-error blocks now emit a WINDOW dataset row
       (row_type=1, fault_class=6) with repeat_count,
       successful_transactions_between_errors, underlying_error_type,
       underlying DUT-detected member count, window_id.
FI-07  High-error-rate windows now emit a WINDOW dataset row
       (row_type=1): fault_class=8 + condition=1 when the threshold is
       met, class 0 + condition=0 when below. Fields: window_size,
       window_faulty, error_rate_pct, threshold, dominant_error_type.
FI-08  CSV separates total_transactions / valid_transactions /
       errors_observed / faults_injected / fault_tests. `error_count`
       (which carried the test-case counter) no longer exists.
FI-09  fault_class and health_label are independent columns. Legal
       health values: 0..8 and 98 only. TWO-BIT rows keep ground truth
       class 1 + expected_limitation_flag=1 (subclass 20 moved to the
       underlying_fault_type column). Reset rows are health 0 event rows.
FI-10  row_type + transaction_id + window_id + event_id +
       ref_transaction_id. Reset/event/window rows carry
       transaction_id=-1 and never reuse a communication id.
FI-11  Wording: "REPEATED ERROR PATTERN OBSERVED (analysis
       classification, NOT hardware detection)". Counter renamed
       repeated_error_patterns_observed; per-block underlying
       DUT-detected members reported separately.
FI-12  Wording: "HIGH ERROR RATE CLASSIFIED (window-level ANALYSIS, not
       hardware detection)". Counter renamed
       high_error_rate_windows_classified.
FI-13  FIFO cases verify the PER-CASE event delta (events_after -
       events_before == planned), never the cumulative counter.
FI-14  Invalid-label rows record original_label, injected_label and
       label_supported=0 columns + framework sanity check that the
       injected label is really outside the application-defined set.
FI-15  Bus-idle classification condition (idle_duration >= IDLE_THRESHOLD
       AND no TX/RX activity) recorded explicitly; new directed GAP
       CONTROL proves a normal 2000-cycle interword gap is NOT classified
       as BUS_IDLE_ERROR.
FI-16  Directed windows added: 0%, 10%, 28% (below), 30% (exactly at the
       >= threshold boundary -> classified), 50% (above).
FI-17  rand_range() guards degenerate ranges; window size clamped 2..64;
       planned faults clamped to window size (no infinite loop); fifo
       depth clamped 1..64; idle threshold clamped above the normal gap;
       timeout threshold clamped >= one transaction; full plusarg set:
       +SEED +MODE +TESTS +PROB +WINDOW +THRESH +TIMEOUT +IDLE +FDEPTH
       +REPMIN +REPMAX.
FI-18  HEALTH_UNRELIABLE=98 written ONLY when a row's verification could
       not be established (framework failure / parity anomaly). A DUT
       miss of a validly injected fault keeps the ground-truth class with
       verification_status=VER_FAIL_DUT. New parity_anomalies bucket for
       "parity flagged but response != bit-accurate prediction". Every
       reset case now runs a post-reset RECOVERY transaction that must
       fully pass before the case can PASS.

COUNTER CONSISTENCY EQUATIONS (all verified holding in simulation)
  E1  total_tests == passed_tests + failed_tests
  E2  faults_injected == faults_detected + faults_undetected
      + expected_limitations + faults_unresolved
  E3  parity_faults == parity_detected + parity_undetected
      + parity_anomalies
  E4  two_bit_faults == two_bit_limitations
  E5  timeout_faults == timeout_observed + timeout_unresolved
  E6  fifo_overflow_events == fifo_overflow_expected_limit
      + fifo_overflow_unresolved
  E7  fifo_underflow_events == fifo_underflow_expected_limit
      + fifo_underflow_unresolved
  E8  invalid_label_faults == invalid_label_expected_limit
      + invalid_label_unresolved
  E9  bus_idle_cases == bus_idle_expected_limit + bus_idle_unresolved
  E10 repeated_error_cases == repeated_error_patterns_observed
      + repeated_error_failed
  E11 high_error_rate_cases == high_error_rate_windows_classified
      + high_error_rate_windows_below + high_error_rate_failed
  E12 normal_tests == normal_passed + normal_failed
  E13 reset_tests == reset_passed + reset_failed
  E14 sum(bit_faults_by_*) == parity_faults
Window-level records (repeated blocks, high-rate windows) never touch
total/passed/failed - their member transactions were already counted;
E10/E11 are the window-level ledgers. This prevents double-counting.
